# Step 8 — Render and Inspect

## Objective

Evaluate the actual rendered experience rather than trusting source code.

## Inputs

- Running implementation

## Actions

Render representative states:

- desktop
- tablet
- mobile
- initial viewport
- mid-page
- lower-page
- interactive states where relevant

Inspect:

- typography
- spacing
- alignment
- hierarchy
- cropping
- section rhythm
- animation
- visual density
- overflow
- accidental empty space

## Critical Questions

- What catches the eye first?
- Is that what should catch the eye first?
- Where does visual rhythm break?
- Where does the page look generic?
- Which section is weakest?
- Is any animation distracting?
- Is any section over-designed?

## Output

A **Visual Inspection Report** containing:

- Observations
- Screens/states reviewed
- Visual defects
- UX concerns
- Priority of fixes

## Stop Conditions

Do not proceed if there are obvious structural visual defects.

## Self-Review

Identify the three weakest visible areas and explain why.
